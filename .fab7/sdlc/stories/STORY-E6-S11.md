## Cross-repo recon (Explore, 2026-07-15)
- **Reference SDK (`../openbox-temporal-sdk-python`) has NO findings loop** (recon-confirmed): `behavioral_violations`/`alignment_score`/`risk_score`/`constraints` are parsed into `GovernanceVerdictResponse` (`types.py:126-143`) but **never surfaced, logged, or delivered** back — the only downstream consumers are `enforce_verdict` (verdict + guardrail `validation_passed`) and input/output redaction. So the findings loop is a **genuine shift-left ADDITION** (like E6-S9 secret detection), not a port. Guardrail reason shape = `{type, field, reason}` (`types.py:117-119`); `behavioral_violations` is free-text `List[str]` (drift), so a content-safe surface must project to COUNTS/CATEGORIES, never the free text.
- **openbox-core `/evaluate` findings are FULLY SYNCHRONOUS** (recon-confirmed, `governance_workflow.go:421-651`): OPA policy + Guardrails + AGE (goal-drift/alignment via LlamaFirewall) all run inline as concurrent activities and return in the SAME response — there is **NO separate findings/drift report endpoint** (only `/governance/approval`, an approval-status poll with no findings). So "async" in the design means **async DELIVERY to the developer** (spooled → flushed at SessionEnd → findings only materialize then), NOT async computation. Reusing the already-parsed `Evaluation` from the flush path is therefore the only + correct source.
- **Wire-shape correction (LOAD-BEARING):** core **never populates** the top-level `behavioral_violations`/`trust_tier`/`alignment_score` fields the client models — drift lives under **`age_result`** (`AGEResult{goal_drifted bool, violations_count int, goal_alignment_checked bool, verdict}`, `content/governance.go:523-535`), which `client/verdict.go` does **not** parse today. Guardrail findings (`guardrails_result.reasons`), `risk_score`, `constraints`, and the `verdict` ARE parsed and available. **Consequence:** the guardrail/verdict/risk half of the goal needs ZERO client change; the **drift** half needs a minimal, content-free `age_result` parse.
- **CC hook output mechanics (claude-code-guide, code.claude.com/docs/en/hooks.md):**
  - **`SessionEnd` output is DISCARDED** — `additionalContext`/`systemMessage`/`decision` are all ignored, stdout/stderr → debug log only (the session is already closed). **So the design's "SessionEnd summary" cannot be delivered at SessionEnd.** The summary is instead delivered at the *next* turn.
  - **`UserPromptSubmit` + `PostToolUse`** both support `hookSpecificOutput.additionalContext` (→ injected into the model's context) and a top-level `systemMessage` (→ shown to the USER only), on exit 0, WITHOUT any blocking field. These are the two viable surfaces.
  - **`SessionStart` is DELIBERATELY NOT used** as a surface: E6-S8 staleness already owns the SessionStart `additionalContext` stdout, and a command hook may emit only ONE JSON object — a second writer would corrupt it. `UserPromptSubmit` (fires at every turn start, including the first prompt) is the collision-free equivalent of a session-start summary.

## The design (a consumer that tails the existing advisory record)
E6-S11 adds no producer and no sink. On the flush path the SL-9 `Advisory.Record` already appends a content-free line per notable evaluation. The findings loop:

1. **Cursor** (`findings.go`): a small state file (`findings.cursor`, `OPENBOX_FINDINGS_CURSOR` override) holds the last byte offset of `advisories.jsonl` that has been surfaced. append-only + O_APPEND → the offset is stable (records are never rewritten).
2. **Surface** (`surfaceFindings(hook, stdout)`), gated on `ResolveFindings()` (default OFF) and called on **UserPromptSubmit** and **PostToolUse**:
   - **Hot-path guard (NFR-2):** `stat(advisories.jsonl)`; if size ≤ cursor offset → return immediately (one stat, no read). Only when new bytes exist does it read the delta.
   - Read `advisories.jsonl` from the offset to EOF, parse the new `advisoryRecord` lines, keep the notable ones, build ONE **content-free summary** (finding count, would-block count + verdicts, guardrail CATEGORIES via `reasonTypeCategories`, drift count, max risk — no free text, no content), emit it as `additionalContext` (→ model, closes the loop with the agent) + `systemMessage` (→ user, the "findings-back-to-dev" goal), then advance the cursor to the new EOF (atomic temp-write + rename).
   - **At-most-once (best-effort):** a rare race between two concurrent PostToolUse processes could show one batch twice; harmless for an advisory surface, documented (no lock — a lock's stranding/staleness cost outweighs a duplicate warning).
   - If the advisory file shrank below the offset (truncation/rotation — not done today, defensive), reset the offset to 0.
3. **Drift** (content-free `age_result` parse, `client/verdict.go`): add a `DriftResult{GoalDrifted, GoalAlignmentChecked, ViolationsCount}` parsed from `age_result` (drop the free-text `reason`/`span_results`/detail — the SAME INV-2 discipline the client already applies to `guardrails_result.redacted_input`/`raw_logs`), a nil-safe `Evaluation.Drift`, fold drift into `IsAdvisory()`, and add content-free `DriftGoalDrifted`/`DriftViolations` to the SL-9 `advisoryRecord`. This is a deliberate, content-free **SL-9 enrichment** (the advisory sink gains drift awareness), scoped tightly and forward-compatible (absent `age_result` → nil → byte-identical parse).

## Config / opt-in (default OFF)
- **`ResolveFindings`** (new, `creds.go`): default **FALSE** (opt-in) — it is the first observe-path stdout writer, so it must be chosen explicitly; with it off, `UserPromptSubmit`/`PostToolUse` write NOTHING and the whole path is **byte-identical to today**. Config `findings` (*bool) / env `OPENBOX_FINDINGS`, env wins; a missing/unreadable config leaves it OFF (fail-safe). **Orthogonal to enforce** — the findings loop is advisory feedback and works in BOTH observe and enforce sessions.

## Invariants
- **INV-2 (no content egress / no content on-disk / no content to model-or-user):** the summary is built ONLY from the content-free `advisoryRecord` fields + `reasonTypeCategories` + drift COUNTS — never guardrail `reason`/`field` free text, `behavioral_violations` strings, `age_result.reason`, tool content, command, or file body. The `age_result` parse drops every free-text/detail field. Nothing new egresses (the surface is LOCAL stdout to the dev's own CC session, not a network sink). The cursor/state files are structural (a byte offset), content-free, 0600.
- **INV-3 (observe never blocks):** the surfacer emits ONLY `additionalContext` + `systemMessage` — never a `decision`/`permissionDecision`/blocking field. It cannot deny, ask, delay, or fail a tool call; every fault (missing file, parse error, bad cursor, write error, panic) is swallowed and the hook proceeds. With findings OFF it is inert.
- **INV-1:** no secret I/O on the surface path (it reads a metadata-only JSONL + a byte-offset file; `ResolveFindings` is a cheap config+env read).
- **NFR-2 (<50 ms hot path):** PostToolUse is stat-guarded — the common case (no new findings) is one `stat` + one tiny cursor read, no delta read.

## Scope boundary (what this story IS and is NOT)
- **IS:** `adapters/claude-code/findings.go` (cursor state, `surfaceFindings`, the content-free summary builder, atomic cursor advance); `ResolveFindings` + `DevConfig.Findings` + `OPENBOX_FINDINGS`/`OPENBOX_FINDINGS_CURSOR` (`creds.go`); the two surface call-sites in `hookrun.go` (UserPromptSubmit + PostToolUse, flag- + stat-guarded); the content-free drift parse in `client/verdict.go` (`DriftResult`, `Evaluation.Drift`, `IsAdvisory` drift clause) + the content-free drift fields on `advisoryRecord` (`advisory.go`); unit tests + conformance.
- **IS NOT:** any new sink/table/endpoint (reuses `advisories.jsonl`; a new one would need an ADR); a producer rewrite (SL-9 `Advisory.Record` unchanged except the additive content-free drift fields); the enforce apply cascade / sidecar / failure policy / Tier-2 (all unchanged); surfacing guardrail/drift FREE TEXT or any content (dashboard-only, INV-2 — the summary points the dev to the dashboard for detail); a SessionStart surface (collides with E6-S8 staleness — UserPromptSubmit is the equivalent); cwd/project scoping of the summary (v1 is a global "recent findings" summary; per-project scoping is a follow-up needing cwd on the advisory record); **NO core/backend surface change** (reuses the `/evaluate` response verbatim; `age_result` is already on the wire).

## Acceptance Criteria
1. **AC-1 (surface a finding):** findings ON, `advisories.jsonl` has a notable record beyond the cursor → on the next UserPromptSubmit/PostToolUse the hook emits `additionalContext` + `systemMessage` with a content-free summary (counts + guardrail categories + drift count + max risk), exit 0. *(Unit + conformance.)*
2. **AC-2 (at-most-once):** after surfacing, the cursor advances; the next hook with no new records writes NOTHING (empty stdout). *(Unit + conformance.)*
3. **AC-3 (opt-in default OFF):** findings OFF → UserPromptSubmit/PostToolUse write NOTHING even with pending records; byte-identical to today. *(Unit + conformance.)*
4. **AC-4 (content-free, INV-2):** the emitted `additionalContext`/`systemMessage` and the cursor/state files contain NO guardrail free text, no `behavioral_violations`/`age_result` free text, no tool content/command/file body — only categories, counts, verdict labels, and a numeric risk. *(Unit asserts the summary string; live E2E greps the surface + state for a seeded secret/reason.)*
5. **AC-5 (INV-3 never blocks):** the surfacer emits no `decision`/blocking field; a corrupt/missing advisory file, an unwritable cursor, or a malformed record is swallowed and the hook exits 0 with (at most) a stderr diagnostic. *(Unit fault-injection.)*
6. **AC-6 (drift, content-free):** a `/evaluate` response carrying `age_result.goal_drifted=true` (verdict ALLOW) is recorded as advisory (drift clause of `IsAdvisory`) with a content-free drift count, and surfaces in the summary as a drift finding — without the `age_result.reason` free text. *(Unit on `parseEvaluation`/`IsAdvisory` + the summary.)*
7. **AC-7 (NFR-2 hot-path guard):** with no new findings the PostToolUse surface path does a single stat (+ tiny cursor read) and no advisory-file body read. *(Unit verifies no delta read when size ≤ offset.)*
