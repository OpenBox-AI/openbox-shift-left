# Phase 02 — the six guards, rebuilt package-scoped

Done 2026-08-30. Every replacement is **co-resident** with the guard it replaces
and both are green on the current, still-multi-module tree. That co-residency is
the equivalence evidence the phase asks for; phase 03 deletes the originals.

## What was built

`cli/internal/depguard/` — one test-only package, three files, no non-test file,
no new dependency anywhere.

**Why one package and not six.** Pre-collapse the guards live in six different
*modules*. A shared helper would need a `require`, a `replace`, **and an allowlist
entry in each of the six** — the exact widening this phase exists to prevent. So
the replacements walk subtrees by **filesystem path** from the repo root, which
needs no module relationship at all. `cli/cmd/openbox/modulewiring_test.go` and
`cli/internal/corpusfixture/committed_test.go` already do precisely this.

| replaces | scope | asserts |
|---|---|---|
| `decision/guard_test.go` | `decision/` | ext `{gitleaks/v8}`, local `{…/client}` |
| `telemetry/guard_test.go` | `telemetry/` | ext = the 11, local **`{}`** |
| `transport/guard_test.go` | `transport/` | ext `{goproxy}`, local `{…/gateway}` |
| `gateway/guard_test.go` go.mod half | `gateway/` | ext **`{}`**, local `{…/client, …/decision}` |
| `conformance/deps_test.go` | the package | module **closure** = `{jsonschema/v6, x/text}` |
| `layering_test.go` extension | both adapters | neither imports the other |

Plus `TestNoReplacePointsOutsideTheRepo`, which is the half of conformance's guard
that has to outlive the phase — a criterion is checked once at merge, a test
forever.

## The defect the phase as written would have shipped

The original spec said the walker should **drop repo-local imports**. Measured
against the real allowlists, that deletes the repo-local half of four of the six:

- `decision` allows `…/client`; `transport` allows `…/gateway`;
- **`gateway`'s entire allowlist is `{…/client, …/decision}` — no external entry
  at all**, so a drop-repo-local walker leaves it with nothing to check;
- `telemetry`'s repo-local set is deliberately **empty**, and that emptiness *is*
  the quarantine its own guard calls out.

Composed with the `cli/internal/*` → `internal/cli/*` flattening, that is a **live
credential regression**: `internal/gateway` could import `internal/cli/devinit`,
which reads and writes `~/.openbox/.env` (`credfile.go:65`), with every rebuilt
guard green. The walker classifies instead of dropping, and the drill
"gateway imports the credential-file package" is RED.

**The flattening is FORCED, not stylistic** — a correction to phase 01's F4 and to
the plan's stated reason. `cmd/openbox` imports **12** `cli/internal/*` packages;
under `internal/cli/internal/*` it sits outside that subtree and could not import
any of them. "Basename collisions and legibility" is the weaker half of the
justification. The compensating control is the repo-local axis above, which
equivalence required anyway.

## Prefix semantics, and why byte-identity needed them

Allowlists name **module** paths; imports name **package** paths. Measured:
`telemetry` allows `collector/pdata` and imports `pdata/{plog,ptrace,pmetric,pcommon}`;
`decision` allows `gitleaks/v8` and imports `gitleaks/v8/{config,detect,report}`;
`gateway` allows `…/client` and imports `client/memhttptest`. Under equality every
one is red on the first run, and the obvious "fix" — rewriting entries to package
paths — grows the lists, which ADR-0023 forbids. Membership is entry-or-subpackage,
with a **slash boundary** so `…/gateway` does not admit `…/gatewayfoo`.

**No allowlist gained or lost an entry.**

**Two drill-harness defects were found and fixed before any result was believed.**
Both produced results that looked like measurements and were not — the shape this
repo already records four times:

1. `printf '%s'` does not expand `\n`, so every planted file was one invalid line.
   Every RED was a **parse error**, not a guard firing — including the stdlib
   control, which cannot fire. The harness now reports `[PARSE ERROR — not a guard
   firing]` explicitly so this cannot recur silently.
2. The neutralisation drill originally mutated `unallowed()`, which has its own
   unit test — so it measured that test rather than isolating the guard. Retargeted
   at `guards()`.

## The finding that outgrew this phase: these guards were cacheable

**Go's test cache does not track files a test reads outside its own package
directory.** Measured 2026-08-30, warm cache, violating file present:

| | cached run | `-count=1` |
|---|---|---|
| newly added violating file | `ok` | FAIL |
| modified existing file | `ok` | FAIL |

**This is pre-existing and repo-wide, not something this phase introduced.** The
same measurement was run against `client/memhttptest/guard_test.go` — warm the
cache, plant a non-test importer, and it returns `ok`. Every guard that walks
outside its package has it: `memhttptest`, `gateway/gatewaytest`,
`cli/internal/corpusfixture/committed_test.go` — whose own header calls it *"the
only control that survives the person who ran the extractor"* and says *"this
particular gate failing open is a credential in git history"* — and
`cli/cmd/openbox/modulewiring_test.go`.

**CI is exposed, not just local runs.** `actions/setup-go@v5` restores
`~/.cache/go-build` by default, and adding a file to `gateway/` does not change
the build ID of `cli/internal/depguard`, so the stale result is served.

Fixed with one flag — `go test -race -count=1 $MODS` in `ci.yml` — with a comment
saying it is a correctness flag and naming the five guards it keeps alive. It is
in scope because shipping a guard already known to serve a stale pass is shipping a
broken control; that it also repairs four pre-existing guards is a side effect of
the same one-word change, not extra work.

## Deliberately not taken

A **root-level direct-require allowlist** over the collapsed `go.mod`'s ~19
modules. The dissolution is real — nine modules have no guard today and lose their
own `go.mod` as a review surface, so anything already in the union graph (`viper`,
`afero`, `zerolog`, the gitleaks tree) becomes importable from `client` or
`provider` with no diff outside a `.go` file. Declined on `--yagni`: it is a **new**
control, not a converted one. Recorded as a named loss for ADR-0023's amendment,
where the owner decides. The cheapest form is ~19 entries with their D-OSS
citations plus a CI `go mod tidy -diff`, and phase 07 is already opening CI.

## Unresolved questions

1. Root direct-require allowlist, or accept the nine-module dissolution as a
   recorded loss? Owner call; the ADR-0023 amendment must say which.
2. `conformance`'s closure check shells out to `go list`. Implemented that way
   because it is the only form that preserves `x/text` — an **indirect**, which no
   import walk can see. If a subprocess in a guard is unacceptable, the fallback is
   `{jsonschema}` alone with the retired closure pin recorded as a loss.
3. The Go-test-cache hole is fixed for CI. A developer running `go test ./...`
   locally without `-count=1` still gets stale passes from all five guards. Worth a
   `CLAUDE.md` line, or a `go.work`-era `GOFLAGS` setting? Not taken here.
