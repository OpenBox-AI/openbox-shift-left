01Verdict
Stronger plan than rev 1 — three loose ends, all ten-minute edits, none architectural.

The local-gateway pivot landed the way the advice predicted: phases 04–06 survived nearly verbatim, the custody machinery (org credential, KMS, HA, fleet rollout) is deleted rather than deferred, and the old kill switch (probe B) is defused into a tier question. Both collisions from review rev 1 are fixed and re-verified in the tree: testbed/45-gateway.sh targets a genuinely free slot, and Content.ToolOutput is pre-decided (grep confirms the name is unclaimed; Content.Output stays with ADR-0018 turn text). One assumption got upgraded to fact this pass: Claude Code's local account state on this machine carries emailAddress, organizationUuid, organizationName, and organizationRole — phase 05's account-stamping source is real, and richer than the plan assumed.

The loose ends are self-inflicted and known: the four validation action items are recorded in plan.md but not yet applied to the phase files — most importantly, phase 06 still says the fail posture "defaults to forward" while the validated owner decision is always refuse, and phase 05 still builds the sink that validation deferred. Plus one carry-over from rev 1 that the update pass missed: the Codex non-goal sentence is still absent from plan.md. Apply those, then Track A and the three probes start in parallel as validated.

P0 — pass-through's coverage
Does BASE_URL carry subscription OAuth?
If not, the gateway tier covers API-key/console orgs only — a product-scope statement, no longer a Track B death. The pre-decided response lives in phase 03's risk table. Run it first; it reuses probe A's server.
Probe A — refusal shape
Refuse without looking transient
Unchanged from rev 1. A wrong shape makes policy denials read as retryable errors. Under always-refuse this matters more: an outage now renders refusals constantly, so the shape must be boringly stable.
P1 — account rule ceiling
Refusal or detection for OAuth?
Local-state half already verified (org UUID + email exist). The in-flight half decides whether a personal-account session is HALTed or flagged. API-key fingerprints refuse either way.
Backend ask 1 · new
Account registry as policy input
Org key fingerprints + allowed org UUIDs, matched server-side → HALT. May be a new surface on core's side — their ADR rule, their call. The evidence contract ships from phase 05 regardless.
Backend ask 2 · new
Session-vs-spans mismatch alert
Turns present, gateway spans absent ⇒ bypass signal. This IS the detection tier's teeth; phase 08 asserts the evidence is queryable, the alert itself is core-side work.
Backend asks 3–4 · carried
Retention + server-side dedupe
Open since ADR-0019/0013 era, unchanged by the pivot. Phase 08 attaches measured volume numbers; retention now covers per-machine spool/sink surfaces instead of one org service.

09Review cards
Good — keep exactly as is
  • The pivot deleted more than it added — custody, KMS, HA, fleet ops gone; one phase rewritten, two lightly touched, Track A untouched.
  • Account binding respects the ADR-0017 dogma: sensors attach evidence, core decides, the gateway renders — phase 06 explicitly forbids building account machinery.
  • Fingerprint-then-redact ordering has its own conformance case, asserted on outbound bytes — the C26 discipline extended to the one derived-from-a-secret field.
  • Validation captured real owner decisions (fail posture, PII scope, sink deferral) instead of rubber-stamping — and recorded the cost of the one that diverges from house posture.
  • Doctor detects the assurance tier by file ownership — no tier flag to lie.
Concerns — fix before implementation
  • Apply the four validation action items — phase 06's "default forward" line and phase 05's sink items now contradict the validated record. Ten minutes, do it before anyone implements from the phase files.
  • Always-refuse raises the ordering test from important to critical — phase 06 should name it a merge-blocker, not just a test.
  • Email is PII on the wire — the data-and-privacy row must land with phase 05, not after; the org-role/name fields found this pass should be explicitly excluded or included, not drifted into.
Gaps — still absent
  • The Codex sentence, again. Rev 1 flagged it, the advice checklist required it, the update pass missed it. Plan.md needs one line: Codex Track B coverage (via OPENAI_BASE_URL) is a non-goal of this plan, revisited after the Claude Code gateway ships. Silence is the only wrong option.
  • Uninstall/opt-out UX for the daemon is specced (init --remove) but the doctor message for "governed but daemon absent" vs "never governed" isn't — minor, phase 07 detail.
Questions — for the owner
  • Always-refuse and offline work: a developer on a plane gets zero gated model calls. Is that the intent (it follows from the decision), or does an explicit "offline grace" ever enter the picture? Recording "no grace, by design" in ADR-0021 pre-empts the first support ticket.
  • Account registry ownership: who on the backend owns the registry ask, and does it need their ADR? Blocks nothing client-side, but the HALT criterion in phase 08 can't pass without it.
