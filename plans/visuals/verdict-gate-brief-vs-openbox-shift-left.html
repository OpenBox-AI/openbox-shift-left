Verdict-gate brief · OB-CC-GATE-v1.0 · 21 Aug 2026

The brief renamed things you already built.

It reads as a 6–7 week greenfield project. It isn’t. Two of its three “new” components are repos that already run in production — under different names. Four things are genuinely missing. That’s the whole story.

Three components in the brief. Two already exist.

Why this matters more than a naming quibble

Building the brief literally means standing up a second pipeline beside the one you have — exactly what this repo’s founding rule (“reuse, don’t rebuild”) exists to prevent. Its open question #9 asks how to reconcile Gate API schemas with existing OpenBox contracts. The answer: don’t — the endpoints are already there.

03 · What is actually missing

Four things. Roughly 2–3 weeks across repos, not 6–7.
01 — the big one
Seal, anchor, verify

Core stores Merkle leaves, but nothing seals a session, returns an anchored root, or verifies a chain offline. No openbox verify exists. The brief’s acceptance demo — and its sales demo — cannot be run today.

core + backend + CLI
02
Slack approval surface

No Bolt app, no Block Kit cards, no /openbox status. Good news: the hold-and-rewake loop already polls whatever decides, so this drops in without touching this repo.

backend / new app
03
Default policy pack

The engine is core’s; nobody ships the rules — destructive FS, curl | sh, protect-the-hook-config. First fix inside that: the proven hole where org locks on base_url / backend_url don’t bind, so a governed agent can re-point the control plane.

backend / templates + this repo
04
Release signing

Checksums only — no signature, no SBOM, no verifying installer. The brief requires a “signed, reproducible static binary”; that claim is currently unbacked.

CI / goreleaser

Smaller items in the same bucket: HMAC hash-preserving redaction (we use category placeholders), input_hash over the raw input, a persisted circuit breaker, latency SLOs — and one live test nobody has run: does a deny hold under --dangerously-skip-permissions? The brief calls that its core selling claim and grades it unverified. It is unverified here too.

04 · Not missing — decided the other way

These need your call, not code
  • Brief wantsFail-closed by default — “the differentiator”
    You shippedFail-open default (ADR-0016). The managed profile even locks fail_closed:false, so that fleet can’t opt in.
  • Brief wantsLocal ask approval first — developer decides
    You shippedRejected (OD-E9-1): approving your own filed request isn’t four-eyes. Undecided denies.
  • Brief wantsHashed inputs by default; raw content never leaves the host
    You shippedFull content capture, ON by default (owner call, 2026-07-15). The brief’s own curl | sh rules need content its default hides.
How to use the document

Not as a build plan — as a requirements audit and a positioning source. Answer the three decisions above, route the four gaps to their repos, and correct its schema section to the existing /evaluate contract. Its best line survives intact: “Slack Code makes agent work visible. OpenBox makes it verifiable” — and “verifiable” is precisely gap 01.
