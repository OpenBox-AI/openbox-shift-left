OpenBox · Convergence Proposal · 2026-08-27

Three Lanes, One Pipeline

openbox-logger ran a live capture on this machine today and proved, with bytes on disk, the three things openbox-shift-left has been unable to prove for a month: that a subscription-OAuth install's model calls are observable, that the desktop app is coverable, and that the full model-call exchange can be captured without redirecting ANTHROPIC_BASE_URL. This document maps the logger's architecture onto shift-left's existing pipeline and names what each dead-end becomes.

repos openbox-shift-left · openbox-logger evidence run 20260827T063932Z-225cac touches ADR-0021 §§5,8,9,10 · proposes ADR-0022
§0

The finding, in one paragraph

Shift-left's gateway observes model calls by redirecting ANTHROPIC_BASE_URL — a lane the desktop app ignores and subscription OAuth may not follow (ADR-0021 §8). The logger observes the same calls through environment lanes the embedded engine honors everywhere: Claude Code's enhanced-telemetry beta (OTEL_LOG_RAW_API_BODIES, OTEL_LOG_TOOL_CONTENT, tool_decision events) and, on the transport side, a loopback TLS proxy scoped to api.anthropic.com. Today's run captured a desktop-app session on a claude.ai login — every one of 97 /v1/messages calls carried an OAuth authorization header, zero carried x-api-key — through both lanes at once. measured 2026-08-27

The proposal is one sentence: hooks enforce; native telemetry observes; an in-path relay fronts model calls — the base-URL gateway on the CLI, the transport proxy (a product service, per OD2) on both clients; refusal awaits probe A. All lanes feed the pipeline shift-left already has — redact → cap → spool → sign → /evaluate — and nothing new is invented server-side. §5 answers the interception question hop by hop: where a verdict lands before the communication, where only monitoring is possible, and how monitored evidence still gets enforcement teeth. Owner update, 2026-08-27: all four §7 decisions are ruled — full-body egress with accepted truncation (OD1 c), the transport proxy as a native product service with a one-command install and a one-command clean removal (OD2), the beta surface accepted (OD3), and telemetry silence treated as a finding with the late HALT accepted (OD4).

§2

What openbox-logger actually is

~1,200 lines of Python plus two pinned containers. Three separate evidence lanes, never averaged together.

The three lanes

  • Transcript lane. A future-only watcher over ~/.claude/projects/**/*.jsonl with a byte-offset cursor, inode-based rotation detection, and invalid-JSON retention. Shift-left's hookflow.TurnCursor is the same idea, narrower.
  • Telemetry lane. Claude Code's own OTel export, switched on via env (CLAUDE_CODE_ENABLE_TELEMETRY + CLAUDE_CODE_ENHANCED_TELEMETRY_BETA), pointed at a loopback collector. The beta adds content events — and OTEL_LOG_RAW_API_BODIES=file:<dir> writes the untruncated Messages API request and response of every model call to local files, referenced from api_request_body/api_response_body events by body_ref.
  • Transport lane (optional). mitmproxy in a container, TLS-inspecting only api.anthropic.com (--allow-hosts), reached via HTTPS_PROXY with a project-scoped CA handed to the client through NODE_EXTRA_CA_CERTS — never the system trust store. Auth headers are redacted before events are written; bodies are kept as evidence.

The disciplines worth stealing wholesale

  • Activation as a recorded transaction. enable writes only the env block of settings.json, stores an exact pre-change backup, the original presence/value of every managed key, and before/after SHA-256. It fails on conflict unless forced; disable restores only managed keys and refuses if a managed value changed underneath it. This is the general form of the lesson shift-left learned the hard way on ANTHROPIC_BASE_URL (first-writer-wins, displaced value remembered).
  • Evidence has a chain of custody. Run-scoped directories, a SHA-256 snapshot manifest over every captured file, and redaction as a derived export that never rewrites raw evidence.
  • Coverage is a table, not a sentence. CAPTURE_MODEL.md states per-signal, per-lane, what is and is not seen — including “permission decisions: transcript not authoritative, tool_decision is.” The same stated-not-averaged posture as COVERAGE.md §3.4.
  • Start ordering as a safety property. Collector up → health-checked → proxy up → CA exists → watcher ready → only then is activation offered. The same invariant ADR-0021 encodes for the gateway unit.
§3

Why this unblocks shift-left

The mechanism behind D1

The desktop app embeds the same engine as the CLI (user-agent observed today: claude-cli/2.1.246 (external, claude-desktop, …)). Routing config — ANTHROPIC_BASE_URL — is read per-client, which is why the gateway sees nothing from desktop. But environment lanes reach the embedded engine regardless of which shell launched it: today's run changed only the env block of ~/.claude/settings.json, and a desktop session emitted OTel, wrote raw bodies, and routed through the proxy. The gateway's blind spot is a property of the lane, not of the traffic.

Rules that survive unchanged

  • One model-call evidence producer per session. Election at init: telemetry, gateway, or transport — exactly one captures, never two — extending ADR-0021's disjoint-namespace rule (:gateway: / :otel: / :proxy:) so core's dedupe never absorbs half the evidence.
  • Signals carry no signal_args; free text rides metadata keys — the core goal-overwrite trap (age.go:112-137) applies to telemetry-sourced events identically.
  • The INV-2 allowlist is untouched. The OTel lane binds at its own edge with its own sentinel test; usage.go's transcript projection and its mutation-tested sentinel stay exactly as they are.
  • Redact before attach, cap at the wire — telemetry content passes the same keyword-driven detector with the same honestly-stated reach (C39's unlabelled-hex limit applies here too).
  • Reuse, don't rebuild: no new control-plane table, endpoint, or service. The receiver is a client-side component; its events are activities and signals shaped by the existing contract.
§5

Interception, answered — gate, tap, or nothing

Can OpenBox evaluate before and after every prompt, tool call, HTTP call, LLM call, and MCP call — and act on the verdict?

Short answer: intercept-before exists exactly where the harness offers an in-path point, and that covers prompts, tool calls, and MCP calls on both clients — synchronously, with the full verdict set. LLM calls are interceptable in-path only where a relay sits on the route: the gateway covers the terminal CLI, and OD2's ruling makes the transport proxy a product service that puts a relay on the desktop/OAuth route too (refusal on both relays awaits probe A). Where no relay is installed, model calls are monitor-only through the OTel lane — an after-the-fact, batched, client-asserted export that cannot return a verdict to the call it describes, by construction. HTTP made by tools is intercepted at tool granularity (the invocation, command verbatim, is judged before it runs), never at wire granularity. And on every surface, “after” interception is bounded by causality, not by OpenBox: a side effect that has run can be evaluated, surfaced, and punished — never revoked.

What keeps the monitor lanes inside the enforcement story is next-boundary binding: every lane's events flow to /evaluate, so evidence that arrives after the fact still produces a verdict — and a HALT lands as the latch, which refuses every later gated hook in the session, resume included. The verdict doesn't reach the call it judged; it reaches everything after it. Evaluation is both-sides everywhere; interception is pre-side, at gates.

§7

Owner rulings & honest limits

All four decisions were ruled by the owner on 2026-08-27 — recorded here with their consequences, plus the limits that stay true no matter what.

OD1 ruled (c) · 2026-08-27 Egress posture for oversized bodies.

Ruling: attempt full bodies and accept ~95% truncation. Model-call bodies ride the existing leg — redact, then cap at 65,536 runes — like every other content field. No digest scheme, no excerpt logic, no new mechanism; the proposed evidence store is retired with it (W5 was reassigned to the transport service). The accepted cost is stated in the limits below: the tail beyond the cap exists nowhere org-side.

OD2 ruled · 2026-08-27 Transport lane: product, native, one command each way.

Ruling: product, not lab — and a native system service, not Docker. The transport proxy ships in the openbox daemon (launchd-managed, like the gateway unit; mitmproxy and Docker retire from the product path), TLS-scoped to api.anthropic.com, CA handled as a credential under ~/.openbox/. Contract: one command installs, configures, and enables everything; one command removes it all — services unloaded, every displaced setting restored from the activation record, CA and local captures deleted — the system as close to untouched as possible. This formally reverses ADR-0021 §5 (W2 records it) and gives desktop/OAuth model calls an in-path point: D1's enforcement half closes once probe A lands.

OD3 ruled · 2026-08-27 Riding a beta surface.

Ruling: accept. The lane ships against CLAUDE_CODE_ENHANCED_TELEMETRY_BETA and OTEL_LOG_RAW_API_BODIES now, with version-pinned probes and doctor-visible silence detection committed as W3 scope — the failure mode is absence, and absence is made observable.

OD4 ruled · 2026-08-27 What silence means.

Ruling: silence is a finding. Hook-lane activity with no telemetry in the same session window emits a finding through the existing findings loop; policy may answer it with a HALT, and the ruling accepts that this HALT is late by construction — it binds at the next gated hook, not at the silent call.

Limits that stay true

  • T3 is suppressible. Anything that edits env kills the lane silently. Telemetry is detection with the same claim tier ADR-0021 §2 already argues — never prevention.
  • Thinking does not ride OTel. Anthropic's export redacts extended thinking unconditionally; the transcript lift (ADR-0019 P3) remains the only thinking source. No change.
  • Desktop model-call enforcement now has a path — through W5's transport proxy only, and only after probe A. Until both land, hooks still enforce that session's tools and prompts, telemetry watches its model calls, and whether desktop honors continue:false session kill is a probe, not a claim.
  • The wire loses the tail (accepted, OD1). ~95% of model-call request bodies exceed the cap, so content-based policy and the org record see at most the first 65,536 runes of a model call; the truncated remainder exists nowhere org-side.
  • The transport CA can impersonate api.anthropic.com to this machine. It is a credential with the same trust boundary as the signing key (ADR-0015): anything running as the developer can read it. Single-host interception and loopback-only listening bound the blast radius; they do not remove it.
  • Asserted identity is not proven identity. organization.id from the client binds sessions for detection; only a credential fingerprint at an in-path point supports refusal.
  • Lane counts never reconcile 1:1 (batching windows differ). Correlation is by session.id / request_id / tool_use_id, never by counting.
  • The redactor's reach is unchanged: keyword-driven, entropy-floored — an unlabelled high-entropy value in a 290 KB body is as invisible as it was in a 64 KiB one. C39's honest limit scales with the volume.
